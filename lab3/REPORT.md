# Отчёт по лабораторной работе №3: линейные модели

## 1. Данные и подготовка

В работе использованы два набора данных.

**Регрессия - `Student_Performance.csv`.** Исходный файл содержит 10 000 наблюдений и 6 столбцов. Целевая переменная `Performance Index`; признаки - `Hours Studied`, `Previous Scores`, `Extracurricular Activities`, `Sleep Hours` и `Sample Question Papers Practiced`. `Extracurricular Activities` преобразован в числовой `Yes` в 1, `No` в 0. После преобразования пропусков и нечисловых значений не обнаружено. Разбиение выполнено функцией `train_test_split` с `test_size=0.2` и `random_state=42`: 8 000 объектов в обучающей и 2 000 - в тестовой выборке.

В собственной линейной регрессии признаки стандартизируются по среднему и стандартному отклонению обучающей выборки. Целевая переменная также стандартизируется на время оптимизации, что делает шаги градиентного спуска устойчивее. После обучения коэффициенты и смещение переводятся обратно в исходный масштаб. Нулевое стандартное отклонение заменяется единицей. История MSE сохраняется в исходных единицах целевой переменной.

**Классификация - `german.csv`.** Файл содержит 1 000 наблюдений и 21 столбец. Целевая переменная `Creditability` расположена в первом столбце; остальные 20 столбцов используются как признаки. В целевой переменной присутствуют два класса: 700 объектов класса 1 и 300 объектов класса 0. Разбиение выполнено с `test_size=0.2`, `random_state=42` и `stratify=target`, чтобы сохранить соотношение классов: обучающая выборка - 800 объектов (560 класса 1 и 240 класса 0), тестовая - 200 объектов (140 класса 1 и 60 класса 0). Пропусков в используемых столбцах нет.

Для собственной логистической регрессии признаки стандартизируются внутри реализации по параметрам обучающей выборки. Для базовой Logistic Regression и KNN масштабирование выполняется через `StandardScaler` в Pipeline. Дерево решений обучается на исходных числовых признаках без масштабирования.

## 2. Гипотезы и эксперименты

**Гипотеза 1.** Стандартизация признаков должна улучшить сходимость градиентного спуска, поскольку признаки имеют разные масштабы. Для собственной линейной регрессии использованы пакетный градиентный спуск, `learning_rate=0.05` и `epochs=800`. На каждой эпохе вычисляется MSE, после чего веса и смещение обновляются по градиентам функции потерь.

**Гипотеза 2.** Логистическая регрессия должна быть подходящей базовой моделью для бинарной классификации. Собственная реализация использует сигмоидальную функцию, бинарную кросс-энтропию и пакетный градиентный спуск с `learning_rate=0.1`, `epochs=1000`. Класс определяется порогом вероятности 0.5.

**Гипотеза 3.** Результаты логистической регрессии, дерева решений и KNN будут различаться из-за различий в предположениях моделей. Все классификаторы обучались и проверялись на одном и том же разбиении. Для sklearn Logistic Regression использованы `max_iter=2000` и `random_state=42`; для Decision Tree - `random_state=42`; для KNN - `n_neighbors=5` (или меньше, если обучающая выборка меньше пяти объектов).

Для воспроизводимости во всех разбиениях зафиксировано `random_state=42`. Собственные реализации не используют готовые `LinearRegression` или `LogisticRegression` для обучения.

## 3. Метрики

### Линейная регрессия

На тестовой выборке из 2 000 наблюдений получена **MSE = 4.0826283985**. Обучающая MSE за 800 эпох уменьшилась с **368.67296775** на первой эпохе до **4.16973585** на последней. Это показывает устойчивое уменьшение ошибки в ходе оптимизации.

### Логистическая регрессия и сравнение моделей

Для положительного класса принят `Creditability = 1`. Метрики рассчитаны на тестовой выборке из 200 наблюдений.

| Модель | ROC-AUC | Accuracy | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|
| Собственная логистическая регрессия | 0.808095 | 0.770000 | 0.801282 | 0.892857 | 0.844595 |
| sklearn Logistic Regression | 0.808571 | 0.770000 | 0.801282 | 0.892857 | 0.844595 |
| Decision Tree | 0.619048 | 0.680000 | 0.771429 | 0.771429 | 0.771429 |
| KNN (k=5) | 0.741190 | 0.720000 | 0.769231 | 0.857143 | 0.810811 |

Бинарная кросс-энтропия собственной логистической регрессии уменьшилась с **0.69314718** на первой эпохе до **0.48213176** на последней. Все значения метрик также сохранены в `experiment_results.json`.

## 4. Выводы

1. Собственная линейная регрессия успешно обучилась пакетным градиентным спуском. Итоговая тестовая MSE составила **4.0826**. Снижение обучающей MSE с 368.6730 до 4.1697 подтверждает сходимость оптимизации на выбранных параметрах.
2. Собственная логистическая регрессия показала ROC-AUC **0.8081** и Accuracy **0.77**. По Accuracy, Precision, Recall и F1 результат совпал с sklearn Logistic Regression; разница ROC-AUC составила около **0.00048** в пользу sklearn. Это указывает на то, что собственная реализация воспроизводит качество стандартной логистической регрессии на данном разбиении.
3. Decision Tree показало худший результат среди сравниваемых классификаторов: ROC-AUC **0.6190**, Accuracy **0.68**. Вероятная причина - отдельное дерево склонно подстраиваться под обучающие данные и хуже обобщать зависимости на тестовую выборку.
4. KNN занял промежуточное положение: ROC-AUC **0.7412**, Accuracy **0.72**. Он уступил логистическим моделям, но превзошёл дерево решений по всем приведённым метрикам, кроме того, что сравнение отражает только одно фиксированное разбиение.
5. По совокупности метрик лучшей моделью на этом эксперименте стала sklearn Logistic Regression, однако преимущество над собственной реализацией практически отсутствует. Выводы относятся к выбранному разбиению и не заменяют проверку на нескольких случайных разбиениях или кросс-валидацию.

## 5. Воспроизводимость

Требуется Python 3.10 или новее. Зависимости указаны в `requirements.txt`.

Установка:

```bash
python -m pip install -r requirements.txt
```

Запуск полного эксперимента из каталога проекта:

```bash
python run_experiments.py
```

Скрипт читает `Student_Performance.csv` и `german.csv`, выполняет подготовку данных, формирует фиксированные train/test-разбиения, обучает модели, рассчитывает метрики и перезаписывает `experiment_results.json` фактически полученными значениями. Для классификации используется разделитель `;`. Файлы контрактов в `grader_contracts/` не изменялись.
